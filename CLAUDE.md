# Open Vis Framework — repo conventions

Monorepo. `apps/web` is a pnpm/Turborepo-managed Next.js app; `platform/`
(the product) is a separate Python/InvenioRDM instance, not part of the
pnpm workspace. See `docs/adr/0001-monorepo-two-apps.md` for the original
two-Next.js-apps shape and `docs/adr/0005-adopt-inveniordm.md` for why
the product side moved off Next.js entirely.

## Layout

- `apps/web` — public landing/docs site. Static export, deploys to
  **GitHub Pages**. No backend, no accounts, no server code belongs here.
- `platform/` — the product (browse/submit Visualization Sheets). An
  **InvenioRDM** instance (Python/Flask), scaffolded via `invenio-cli`,
  deploys to the same **self-hosted server** as before via Docker
  Compose over SSH from GitHub Actions
  (`docs/adr/0002-self-hosted-platform.md`, `docs/adr/0003-dockerize-same-server.md`
  for the *pattern*; `docs/adr/0005-adopt-inveniordm.md` for why this is
  InvenioRDM and not the earlier Next.js `apps/platform`, which this
  replaced — see git history if you need the old implementation).
  See `docs/ROADMAP.md` for what's done/still-known-incomplete (auth is
  local-login only for now, no OAuth; no search facets yet).
- `packages/*` — shared code (UI components, types, config). Doesn't exist
  yet; only add a package here once ≥2 apps actually need to share it.
- `docs/adr/` — architecture decision records. Add one for any decision
  that would otherwise get re-litigated or re-derived later (framework
  choices, hosting, data model shifts, etc.).

`apps/web` has its own `AGENTS.md` — auto-generated/maintained by the
Next.js CLI itself, warns that this Next.js version may differ from an
agent's training data, and points at the bundled docs in
`node_modules/next/dist/docs/`. Read it before writing Next.js code there;
don't hand-edit it, it's regenerated by `next dev`.

`platform/` is a `uv`-managed Python project (see its own `pyproject.toml`
and `docs/ROADMAP.md`) — not part of any pnpm/Turborepo command below.

## Commands (run from repo root)

```
pnpm install       # installs apps/web's dependencies
pnpm dev           # turbo run dev — apps/web only
pnpm build         # turbo run build — apps/web only
pnpm lint          # turbo run lint — apps/web only
```

For `platform/`: see `docs/ROADMAP.md`'s "Local dev" section
(`invenio-cli install` / `invenio-cli services setup` / `invenio-cli run`).

## Working conventions

- `apps/web` is still a placeholder scaffold (no real features). Don't
  add product code, database clients, or auth to it — that's `platform/`'s
  job now, not `apps/web`'s.
- Keep `apps/web` free of anything that needs a server (API routes, auth,
  database calls) — it's a static export and will silently fail to build
  those.
- No `LICENSE` or `CODE_OF_CONDUCT.md` yet — both are deliberately deferred
  (see ADR 0001), don't add license headers to files until that's decided.
