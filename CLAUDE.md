# Open Vis Framework — repo conventions

Monorepo, managed with **pnpm workspaces** + **Turborepo**. See
`docs/adr/0001-monorepo-two-apps.md` for why it's shaped this way.

## Layout

- `apps/web` — public landing/docs site. Static export, deploys to
  **GitHub Pages**. No backend, no accounts, no server code belongs here.
- `apps/platform` — the product (browse/submit/moderate visualization
  projects). Server-rendered Next.js, deploys to a **self-hosted server**
  (pm2 + an existing shared Traefik instance) via SSH from GitHub Actions.
  See `docs/adr/0002-self-hosted-platform.md`. This is where auth,
  database, and upload logic will live once built.
  - The server's OS has an old glibc that can't run Next's default
    Turbopack build — use `pnpm --filter platform run build:webpack`
    there specifically. CI/Vercel-style/local builds keep using the
    normal `build` script (Turbopack, faster) — don't change the default.
- `packages/*` — shared code (UI components, types, config). Doesn't exist
  yet; only add a package here once ≥2 apps actually need to share it.
- `docs/adr/` — architecture decision records. Add one for any decision
  that would otherwise get re-litigated or re-derived later (framework
  choices, hosting, data model shifts, etc.).

Each app also has its own `AGENTS.md` — auto-generated/maintained by the
Next.js CLI itself, warns that this Next.js version may differ from an
agent's training data, and points at the bundled docs in
`node_modules/next/dist/docs/`. Read it before writing Next.js code in that
app; don't hand-edit it, it's regenerated by `next dev`.

## Commands (run from repo root)

```
pnpm install       # installs all workspace packages
pnpm dev           # turbo run dev — both apps in parallel
pnpm build         # turbo run build — both apps
pnpm lint          # turbo run lint — both apps
```

Scope to one app with `pnpm turbo run build --filter=web` (or `platform`).

## Working conventions

- Both apps are currently placeholder scaffolds (no real features). Don't
  add product code, database clients, or auth to either app without it
  being an explicit ask — the platform's data model/backend hasn't been
  decided in code yet, only sketched in ADR 0001.
- Keep `apps/web` free of anything that needs a server (API routes, auth,
  database calls) — it's a static export and will silently fail to build
  those.
- No `LICENSE` or `CODE_OF_CONDUCT.md` yet — both are deliberately deferred
  (see ADR 0001), don't add license headers to files until that's decided.
